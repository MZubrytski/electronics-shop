# @shop/web

Nuxt 4 + Nuxt UI 4. Порт 3000.

Общие правила репозитория — в [корневом CLAUDE.md](../../CLAUDE.md).
Требования к страницам — в [docs/PRD.md](../../docs/PRD.md), разделы 4 и 5.
**Все визуальные решения — в [docs/DESIGN.md](../../docs/DESIGN.md).** Палитру,
шрифт, шкалу и сетку оттуда не изобретаем заново.

## Nuxt 4: исходники лежат в `app/`

Главное отличие от Nuxt 3 и от большинства статей: `srcDir` теперь `app/`.

```
apps/web/
  app/               ← сюда пишем весь фронтенд
    app.vue
    app.config.ts
    assets/css/main.css
    pages/           ← страницы здесь, НЕ в apps/web/pages
    components/
    composables/
    layouts/
    middleware/
  server/            ← а вот server остаётся в корне приложения, вне app/
  public/
  nuxt.config.ts
```

Ошибиться уровнем легко: `apps/web/pages/` Nuxt просто не увидит.

## Маршрутизация ещё не включена

Сейчас в `app/app.vue` лежит разметка напрямую и папки `app/pages/` нет.
Как только она появится, `app.vue` обязан содержать `<NuxtPage />`, иначе
страницы не отрисуются:

```vue
<template>
  <UApp>
    <NuxtPage />
  </UApp>
</template>
```

`<UApp>` — обязательная обёртка Nuxt UI: без неё не работают тосты, тултипы
и программные оверлеи.

## Nuxt UI

Подробности API компонентов — в скиле `nuxt-ui` и через MCP-сервер Nuxt UI.
Здесь только то, что относится к этому проекту:

- **Иконки** — набор `lucide`, он уже установлен: `i-lucide-shopping-cart`.
  Эмодзи вместо иконок не используем.
- **Только семантические цвета:** `text-muted`, `bg-elevated`, `border-default`.
  Сырые классы Tailwind вроде `text-gray-500` ломают тему — запрещены.
- **`text-dimmed` для читаемого текста запрещён** — контраст 2.63:1, не проходит
  WCAG AA. Подробности и таблица — в DESIGN.md §3.
- Своего компонента рейтинга в Nuxt UI нет — звёзды пишем сами на `UIcon`.
- Настройки темы: цвета в `app/app.config.ts`, токены и шрифт в
  `app/assets/css/main.css`.

## Данные и авторизация

Токены живут в **httpOnly-куках** (PRD §9.1), поэтому браузер не может читать
их из JS. Отсюда правило:

- Запросы, которым нужна авторизация, идут **через свои серверные маршруты**
  в `server/api/*`, которые проксируют в NestJS и пробрасывают куку.
- Обращаться из браузера напрямую в API по `NUXT_API_URL` для таких запросов нельзя.
- `useFetch` на странице с SSR должен корректно передавать заголовки — иначе
  на сервере запрос уйдёт без куки и вернёт 401.

## Переменные окружения

Nuxt связывает их с `runtimeConfig` по имени автоматически:

| Переменная             | Куда попадает                  | Видна браузеру |
| ---------------------- | ------------------------------ | -------------- |
| `NUXT_API_URL`         | `runtimeConfig.apiUrl`         | нет            |
| `NUXT_PUBLIC_SITE_URL` | `runtimeConfig.public.siteUrl` | да             |

Всё, что попадает в `public`, уезжает в браузер. Секретам там не место.

## Рендеринг

| Маршруты                          | Режим        | Почему                                    |
| --------------------------------- | ------------ | ----------------------------------------- |
| `/`, `/catalog`, `/product/:slug` | SSR          | нужны для SEO (PRD §10)                   |
| `/admin/**`                       | `ssr: false` | закрытая часть, задано в `nuxt.config.ts` |
| `/checkout`, `/account/**`        | клиент       | приватные данные                          |

## Состояние фильтров — в URL

Фильтры, сортировка и страница каталога живут **в query-параметрах** (PRD §5.1).
Не в Pinia, не в `localStorage`. Ссылку должно быть можно переслать, а перезагрузка
не должна сбрасывать выбор.

## Каждый список рисуется в четырёх состояниях

Загрузка (скелетоны, не спиннер), пусто, ошибка, данные. Пустое состояние
всегда с кнопкой действия. Подробности и тексты — DESIGN.md §12.

## Чего здесь нет

- **Нет проверки типов.** Скрипта `typecheck` в этом воркспейсе не заведено,
  и CI её не гоняет. Добавлять — вместе с `vue-tsc`.
- **Нет `@nuxt/image`.** Для Cloudinary его нужно будет поставить отдельно.
- **Нет тестов.** Компонентные тесты по PRD §10 — на Testing Library.
